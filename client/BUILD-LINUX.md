# Сборка Linux для разработчика

Этот документ предназначен разработчику. Он описывает повторную сборку из checkout, а не подтверждает готовность нового выпуска. Пользователь запускает уже проверенный ELF из папки `Linux`. Исходные файлы приложения общие с macOS и Windows.

Нужны Docker с поддержкой целевой платформы (для чужой архитектуры — настроенная эмуляция) и полные ресурсы `assets`, `client/ui`, `server`, `frontend`, `screenshots/real`. Runtime-инструкция входит в отслеживаемые исходники `client/resources/README-LINUX.md`; сборщик копирует её в приложение и архив, не читая заранее существующий каталог результатов `Linux`. Ресурсы должны быть подготовлены до сборки; обёртка их не скачивает и не подменяет. Из корня checkout:

```sh
./client/build-linux.sh x86_64
./client/build-linux.sh aarch64
```

Обёртка определяет checkout относительно собственного расположения, поэтому её можно вызвать и из другой текущей папки. В контейнер монтируется только checkout в `/workspace`, а промежуточная папка — отдельно в `/buildwork`. По умолчанию на хосте это соседняя папка `<checkout>-build/linux/<architecture>`; родительская папка checkout в контейнер не передаётся. Для доверенного разработчика предусмотрено явное переопределение корня промежуточных файлов:

```sh
ONIONDESK_BUILD_ROOT="/absolute/path/with spaces/linux-build" ./client/build-linux.sh x86_64
```

Архитектура добавляется к этому пути автоматически. Относительное значение `ONIONDESK_BUILD_ROOT` разрешается относительно текущей папки вызывающей оболочки. Выбирайте новую пустую папку или предыдущую папку сборки OnionDesk; проверки маркеров владения в Python-сборщике сохраняются.

Сборка использует Linux-контейнер нужной архитектуры и зафиксированный образ `python:3.12.13-slim-bookworm` по digest. Полный набор Python-зависимостей зафиксирован в `client/build-linux-requirements.txt`; версии Paramiko и requests соответствуют общему `client/requirements.txt`, PyInstaller — 6.22.3. Версии Debian-пакетов записываются в происхождении сборки; повторная сборка может включать обновления безопасности Debian и не обещает побитового совпадения.

На выходе создаются `Linux/<architecture>/OnionDesk/OnionDesk`, папка зависимостей `_internal` и архив `Linux/OnionDesk-Linux-<architecture>.tar.gz`. Python, requests, SOCKS, Paramiko, криптографические зависимости, сертификаты и ресурсы интерфейса включены в программу. Linux-сборка открывает интерфейс в браузере по умолчанию. Встроенный WebView и его GTK/Qt-зависимости ей не нужны.

GPG копируется из Debian вместе с рекурсивным набором библиотек, кроме системной glibc. Для каждой скопированной библиотеки задаётся относительный RPATH; поэтому проверка подписи не зависит от установленного на целевом компьютере GPG. Программа запускает проверку повторно с правами обычного пользователя перед записью USB. Вариант PyInstaller `onedir` сохраняет доступ к этим публичным файлам при снижении прав.

Проверка готового файла:

```sh
build_root="${ONIONDESK_BUILD_ROOT:-$(pwd)-build/linux}"
python3 client/build-linux-smoke.py --architecture x86_64 --work "$build_root/x86_64"
python3 client/build-linux-smoke.py --architecture aarch64 --work "$build_root/aarch64" --port 54392
```

Команды выполняются из корня checkout, после успешной сборки соответствующей архитектуры. При переопределении рабочего корня передайте smoke-драйверу тот же путь; переменная, заданная только перед одной командой сборки, не сохраняется в оболочке. Драйвер запускается с Python 3.11+ на машине разработчика. Целевой контейнер — чистый Debian 12 без Python/GPG, с пользователем nobody, без capabilities, с read-only корнем и без устройств хоста. HTTP-проверки выполняет отдельный контейнер в той же сетевой среде: сервер приложения слушает исключительно loopback, поэтому публикация Docker-порта не используется. Проверяются открытие браузера, включённые ресурсы, HTTP403 при отсутствии nonce/неверном Host, состояние приложения, реальная проверка корректной и изменённой подписи, импорт сетевого движка, отказ при отсутствии Tor, завершение и отказ непривилегированному помощнику. Настоящие USB-операции и внешние загрузки не выполняются; Docker может загружать образы.

Логи и временные файлы остаются в `<checkout>-build/linux/<architecture>` либо в выбранном корне. Сборщик заменяет только папку, помеченную собственным маркером, и распознаваемую папку ранее собранного OnionDesk. Smoke-проверка требует маркер уже созданной сборщиком рабочей папки; существующая непустая папка `smoke` также должна иметь собственный маркер. Ссылки и чужие папки отклоняются до изменения их содержимого. Успешная упаковка и smoke-проверка не заменяют проверку на целевом Linux и реальном USB перед выпуском. Полный публичный набор `OnionDesk-Data` готовится отдельно по каталогам проекта.

Ограничение glibc следует из [официальной документации PyInstaller](https://pyinstaller.org/en/stable/usage.html#making-gnu-linux-apps-forward-compatible): glibc не включается в пакет, поэтому программа требует версию не старее, чем при сборке. Формат и размещение ресурсов описаны в [документации о работе PyInstaller](https://pyinstaller.org/en/stable/operating-mode.html) и [описании `_MEIPASS`](https://pyinstaller.org/en/stable/runtime-information.html). Для внешних системных программ применяются [правила окружения PyInstaller](https://pyinstaller.org/en/stable/common-issues-and-pitfalls.html#launching-external-programs-from-the-frozen-application).
