# Локальный мастер OnionDesk

Актуально: 15 октября 2026.

`start_app.py` запускает `app.py`. Backend использует Python stdlib и слушает только `127.0.0.1` на случайном порту. Исходный запуск открывает только локальный интерфейс в стандартном браузере. Frozen `.app` использует встроенное окно pywebview/WebKit при наличии библиотеки; исходный режим может выбрать его через `--native`. Внешние адреса представлены как копируемый текст. Интерфейс не открывает `.onion` или сайты провайдеров в обычном браузере.

Интерфейс содержит 14 целей (00–13), 65 последовательных действий и 65 локальных PNG `assets/microsteps/gNN-sNN.png`. Цели: план и устройство, Tor, создание кошелька, получение XMR, необязательный VPN, Tails USB, аренда сервера, номер Telegram, установка сервера, первый Whonix, сохранение доступа, загрузка Tails/Tor, ежедневный вход и очистка данных файла. В каждой цели показано одно действие; художественные иллюстрации отмечены отдельно от настоящих кадров испытаний. Для Apple Silicon предусмотрен Tor Browser: Tails на этом Mac не загружается, но создание USB для совместимого компьютера доступно.

Обложка обслуживается по `/assets/agent-cover.png` из `KIT/assets/agent-cover.png`; микрошаги, прежние иллюстрации и реальные кадры — только по явным allowlist в `app.py`. GET `/api/guide-shots` возвращает существующие разрешённые кадры с подписями об их происхождении и пределах проверки; HTTP не принимает путь к снимку. CSS, JS и JetBrains Mono Regular/Bold локальные; нет внешних шрифтов, аналитики, CDN или сохранения состояния в браузере.

## Локальная граница доступа

На macOS при запуске комплекта из пользовательского каталога сначала открывается основное окно, затем системный NSOpenPanel с точной папкой `OnionDesk-Data`. До её подтверждения состояние использует неподключённые placeholders: manifest и личные хранилища не читаются, действия с ними запрещены. Выбор другой папки или отмена закрывает мастер. Доступ к выбранному публичному каталогу удерживается только до завершения окна; bookmark и глобальные разрешения не сохраняются. В обычном Applications-каталоге дополнительное окно не требуется.

Каждый запуск создаёт криптографический nonce в памяти. Стартовая локальная ссылка передаёт его через fragment, который JavaScript сразу удаляет из адресной строки и текущей записи истории. В API nonce передаётся только заголовком `X-App-Nonce` и только на относительные локальные пути. Он не сохраняется в файле, cookies, localStorage или sessionStorage. Поэтому обновление страницы требует открыть приложение заново; сообщение явно объясняет это. Неподтверждённая локальная страница не имеет доступа к API.

Каждый запрос проверяет единственный точный `Host` (`127.0.0.1:PORT`); присутствующий `Origin` должен точно совпадать с локальным адресом. Мутации требуют точный Origin и nonce. Cross-site `Sec-Fetch-Site` отклоняется, CORS отсутствует. Все `/api/*`, включая состояние, диски, карточку доступа, памятку, список кадров и кошельки, требуют nonce. Статические ресурсы обслуживаются по явному whitelist; нет чтения произвольного файла, произвольной команды или вызова shell с HTTP-значениями.

POST принимает только JSON до 16 KiB, отклоняет transfer encoding, повторяющиеся JSON-поля и не-объект. Ответы имеют `Cache-Control: no-store`, CSP с локальными script/style/image/font/connect источниками без inline-разрешений, `frame-ancestors 'none'`, `base-uri 'none'`, `form-action 'none'`, `object-src 'none'`, `no-referrer` и `nosniff`. Запросы, тела и исключения не пишутся в лог. Ответы с прогрессом не включают карточку доступа или seed; onion-адрес в тексте прогресса скрывается. Пароль root очищается в поле сразу после отправки, не сохраняется как состояние приложения. SSH-сеанс хранится в памяти до закрытия.

Карточка доступа выводится по явному действию пользователя. Значения устанавливаются как текст/read-only inputs; HTML из удалённых ответов не исполняется. Пароль и TOTP-ключ изначально скрыты. Переход на другой этап и pagehide удаляют значения из DOM. Можно удалить карточку из памяти backend, затем заново получить её с собственного сервера. Системный буфер обмена после копирования пользователь очищает самостоятельно.

По отдельной кнопке «Подготовить адрес для Tails» GET `/api/access-note` возвращает `{text, filename}`: текстовую памятку с onion-URL и шагами, без login, пароля, root-данных и TOTP. UI показывает `text` как значение read-only textarea `handoff-note`; `filename` не используется для автоматического скачивания. Это работает и в native WebView с запрещёнными загрузками. Экспорта через `window.open`, browser download, localStorage/sessionStorage или Python bridge нет. Пользователь копирует текст в свой редактор и выбирает печать/второй носитель. Памятка очищается вместе с карточкой при `hideSecrets`, смене этапа, `pagehide` и удалении карточки. Счётчик запроса не позволяет запоздавшему ответу заново показать скрытую памятку. Сам URL остаётся чувствительными сведениями о расположении кабинета.

## Разрешённые действия

- USB: `usb_tails.system_info()`, `list_usb_disks()`, `download_verified_image(progress_cb, cancel_event)`, `write_verified_image(selection_id, 'СТЕРЕТЬ', progress_cb, cancel_event)`. HTTP не передаёт путь образа или диска. Engine повторно проверяет непрозрачный идентификатор носителя и использует только собственный проверенный образ. Запись никогда не начинается при вставке USB; нужно выбрать флешку и явно ввести `СТЕРЕТЬ`.
- Tor: подготовка/запуск комплектного подписанного Tor Browser через `offline_bundle`, затем проверенный `launcher.find_tor_proxy()`. Нет прямого fallback; наличие запущенного браузера само по себе не подтверждает Tor.
- Соединение: `launcher.validate_host`, `validate_fingerprint`, `connect`; SHA256 берётся из консоли провайдера отдельной фиксированной командой. Проверка root/Debian 13 — фиксированная команда.
- Установка: только `launcher.install`; отдельные обязательные подтверждения свежего сервера и условий Whonix. По умолчанию `tor_mode="public-obfs4"`; `wizard`/`direct` совместимы на уровне launcher. Через проверенный SSH/SFTP-сеанс внутри Tor передаются 27 файлов `RUNTIME_FILES` с проверкой SHA-256. В их числе `server/first_boot.py`, `server/host_tor.py`, `server/oniondesk-first-boot.service` и `server/public-obfs4.conf`. Загрузка в панель провайдера не нужна. Порядок автоматического SYSMAINT, нормального USER и текущей QGA readiness описан в [серверном контракте](../server/CONTRACT.md).
- Возврат к установке: POST `/api/server/resume` через кнопку `resume-install` проверяет серверное задание и продолжает получение его результата. UI не начинает новую установку при восстановлении связи.
- Повторное получение карточки: только два фиксированных серверных файла через проверенный SSH/SFTP-сеанс и проверка формата onion/полей.
- Управление: фиксированные действия `start`, `status` и `audit` через POST `/api/server/action`. На последнем действии цели 09 статус подключённого установленного сервера запрашивается автоматически, без другого задания и не чаще раза в 15 секунд. Готовность объявляется только по текущему гостевому отчёту `ГОТОВО: Telegram…`; успешная установка или наличие VM не выдаётся за готовность.
- Аудит защиты запускается отдельно кнопкой `audit-server`. UI читает `safety_checked`, `safety_ok`, `safety_report` из состояния; отчёт устанавливается через `textContent` в `safety-report`. Успех относится только к выполненным проверкам конфигурации, не к полноте анонимности и не к выбору аккаунта пользователем.

Все длительные действия идут в одном фоновом worker; повторный параллельный запуск запрещён. Прогресс содержит ограниченный список последних событий. Можно остановить загрузку; запись USB и серверная установка не прерываются через UI. API quit и закрытие native окна отклоняются, пока операция выполняется. У приложения нет поля для пароля администратора ОС: native повышение прав обслуживает отдельный USB helper.

## Локальный кошелёк Monero

Шесть модулей разделяют ответственность: `wallet_catalog.py` закрепляет официальный Monero **0.18.5.3** и хеши; `wallet_bundle.py` проверяет подписанный список хешей издателя, архив и извлечённый RPC; `wallet_engine.py` выполняет фиксированные offline RPC; `wallet_security.py` подтверждает шифрование; `wallet_vault.py` управляет личным хранилищем; `wallet_controller.py` управляет секретами и проверкой резервной копии. Единственный controller создаётся под lock `Desk`; параллельные запросы состояния/forget не создают второго владельца хранилища.

UI поддерживает только mainnet и ровно один кошелёк на личное хранилище. Создание выполняется официальным `monero-wallet-rpc` с `--offline --no-initial-sync`, loopback listener, временной Digest-аутентификацией и проверкой процесса. Разрешены только `get_version`, `create_wallet`, `get_address`, `query_key`, `open_wallet`, `close_wallet`. В интерфейсе нет передачи RPC method/daemon/network/path/binary, синхронизации баланса или отправки XMR. Пополнение, обмен и оплата выполняются пользователем отдельно; контракт не подтверждает совершённые платежи.

На macOS для каждого кошелька создаётся собственный native AES-256 sparsebundle; пароль передаётся `hdiutil` через stdin, не сохраняется в файле и не помещается в аргументы процесса. В Windows/Linux личная папка разрешается только после подтверждения существующего BitLocker/LUKS и допустимой памяти подкачки. Неизвестное состояние, недоступность проверки или незащищённый путь запрещают создание/открытие. Приложение не включает системное шифрование и не форматирует диски. Чужие и прежние общие данные не удаляются и не мигрируются автоматически.

GET `/api/wallet/list` возвращает публичные записи и список хранилищ. POST `/api/wallet/{create,unlock,reveal,seed,confirm,forget,lock}` принимает точные схемы полей, с общими nonce/Origin и запретом параллельных операций. Пароль имеет длину 12–256 символов. После create или повторного ввода пароля seed подготовлен только в RAM на 180 секунд. Отдельный `/seed` выдаёт 25 английских слов и challenge для трёх случайных разных позиций; общие опросы состояния seed не возвращают. Подтверждение сравнивает слова, wallet ID и challenge; неверные или просроченные данные не подтверждают резервную копию.

DOM хранит показанные слова не дольше 170 секунд. Смена цели/действия после показа, скрытие документа, `pagehide`, кнопка скрытия и завершение очищают поля, слова и challenge; `/forget` сбрасывает серверные временные секреты и отменяет запоздалую публикацию. Повторный показ требует пароль. `/lock` забывает временные секреты и закрывает рабочее хранилище; на macOS отсоединяет принадлежащий приложению образ. При ошибке закрытия данные сохраняются для восстановления. Python освобождает ссылки, но не гарантирует физическое стирание всех копий RAM. Слова и пароль не копируются автоматически и не сохраняются браузером.

## Frozen ресурсы

PyInstaller datas должны включать `client/ui` (со шрифтами), `assets`, `screenshots/real`, `server`, `frontend` относительно `sys._MEIPASS`. В сборку входят `launcher`, `usb_tails`, `usb_privileged`, `offline_bundle`, `offline_catalog` и шесть wallet-модулей. Перед запуском UI аргумент `--usb-privileged` передаётся в `usb_privileged.main(sys.argv[2:])`. Это нужно для system-native повышения прав: frozen helper запускается текущим бинарником. Source helper сохраняет собственный изолированный Python запуск. Cache управляет USB engine; приложение не записывает данные в readonly `.app`.

Общая папка `OnionDesk-Data` поставляет официальный подписанный IMG Tails **7.15**, Tor Browser **15.0.25** и Monero **0.18.5.3** для поддерживаемых платформ, ключи и подписи. Пути/размеры/хеши закреплены в каталогах программы; внешний manifest не расширяет разрешённый список. При наличии повреждённого офлайн-комплекта подготовка останавливается. Образ Tails проверяется локально без сети; только отсутствие папки допускает существующую загрузку через проверенный Tor. Подробности записи — в [USB-CONTRACT.md](USB-CONTRACT.md).

Native окно использует `private_mode=True`, без прикладного `js_api`/Python bridge. Весь frontend имеет только относительные ссылки/кнопки копирования; обычная внешняя навигация не предусмотрена. Backend живёт до закрытия окна или явной кнопки завершения. Готовые пакеты для macOS ARM64, Windows x64 и Linux x86_64/aarch64 содержат Python и зависимости; пользователю не нужно устанавливать Python или собирать программу. Native `.app` для Mac Intel отсутствует. Для Linux ARM64 в комплекте нет стабильного Tor Browser; наличие ELF не снимает эту зависимость. Windows устанавливается в Program Files и запускает frozen EXE обычным ярлыком; Linux ELF поставляется вместе с `_internal`. Windows собрана и ограниченно проверена под Wine, Linux — целевыми сборщиками; это не заменяет испытания настоящего UAC, polkit, GUI и записи USB.

## Проверка

Backend и UI проверяются отдельно: nonce/Host/Origin всех API, карточка/памятка, CSP/no-store/no-CORS, подтверждение USB, allowlist управления и снимков, согласие установки, JSON, whitelist файлов, запрет параллельных операций и guest readiness. Wallet-проверки охватывают запрет неподтверждённого шифрования, mainnet, create/unlock/reveal, challenge, expiry/forget, singleton controller и lock. Нативное создание mainnet-кошелька без средств в Mac AES-256 vault проверено отдельно; реальные Windows BitLocker/Linux LUKS требуют платформенных испытаний. Актуальные результаты и ограничения приведены в [CHECKS.md](../CHECKS.md); наличие сборок или успешного code review не означает полного прогона сервера, оплаты XMR, регистрации Telegram или доставки SMS. Новый автоматический холодный first boot и физический Debian/KVM подтверждаются отдельно.

pywebview API сверена с [первичной документацией](https://pywebview.flowrl.com/api/): `create_window`, lifecycle events и `start(private_mode=True)`.

## Проводник после записи USB

Цель 05 содержит три действия записи: подготовить проверенный образ, выбрать свою флешку, явно подтвердить стирание и дождаться проверки записи. Цель 11 содержит шесть подсказок загрузки: закрыть файлы/выключить, открыть меню загрузки с выбором производителя, Welcome to Tails/язык, Wi-Fi/кабель, встроенный Tor Connection/bridges и сохранённый onion-адрес. «Предыдущее действие»/«Следующее действие» меняют подсказку; блок «У меня другой результат» открывает контекстную помощь. Переход не управляет BIOS/Tails и не подтверждает результат операции.

Перед перезагрузкой предложено сначала настроить сервер, сохранить пароль и TOTP отдельно и подготовить текстовую памятку с одним onion-адресом и шагами. Руководство нужно открыть на другом устройстве или распечатать. В Tails памятка открывается текстовым редактором через «Файлы», адрес вставляется в Tor Browser; затем штатные Tor Browser Bookmarks в Persistent Storage могут сохранять сам onion-URL. Нет autorun, ввода Wi-Fi пароля в OnionDesk или автосохранения секретов на флешку. Объяснены добровольный Persistent Storage с ручной разблокировкой и предел доверия чужому аппаратному обеспечению.

Типичные клавиши загрузки сверены с первичными страницами, зависят от модели:

- [Dell F12](https://www.dell.com/support/kbdoc/en-km/000128928/flashing-the-bios-from-the-f12-one-time-boot-menu).
- [Lenovo F12/Fn+F12](https://support.lenovo.com/sn/en/solutions/ht500207).
- [HP Esc → F9](https://support.hp.com/bg-en/document/ish_6930187-6931079-16).
- [ASUS Esc при включении](https://www.asus.com/global/support/faq/1013017/).
- [Mac Intel Option](https://support.apple.com/en-gb/102603).

Проводник использует [Tails Welcome Screen](https://tails.net/doc/first_steps/welcome_screen/index.en.html), [подключение к локальной сети](https://tails.net/doc/anonymous_internet/networkmanager/index.en.html), [Tor Connection](https://tails.net/doc/anonymous_internet/tor/index.en.html) и [Persistent Storage](https://tails.net/doc/persistent_storage/configure/index.en.html).


Повседневный обмен пользовательскими файлами между локальным устройством и Workstation не является возможностью noVNC в этом комплекте. UI объясняет разницу между автоматической передачей установщика и отдельным сценарием файлового обмена. Метаданные и вход в личные аккаунты не устраняются Tor; Unsafe Browser в Tails используется только для captive portal и закрывается после входа в сеть.
