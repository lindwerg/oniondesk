# Компонент защищённого входа

Это часть комплекта OnionDesk для **Debian 13 amd64**. Основной установщик вызывает `install-auth.sh <hostname.onion>` после появления настоящего адреса Tor v3. Самостоятельное развёртывание этого компонента не создаёт виртуальные машины или onion-сервис.

Вход: имя **owner**, уникальный случайный пароль и TOTP — шестизначный код, который меняется каждые 30 секунд. Секрет добавляют в совместимое приложение-аутентификатор вручную либо через `otpauth_uri`. Коды SMS здесь не используются. Допускается соседний интервал ±30 секунд, поэтому часы сервера и устройства должны совпадать. Уже использованный код нельзя применить снова; дождитесь следующего. Последний принятый интервал сохраняется на диске и переживает перезапуск службы.

Первая страница `/login` создаёт короткую CSRF-сессию и форму. Неверный пароль или код показывают одно общее сообщение. После пяти ошибок в течение пяти минут новые попытки блокируются на десять минут для единственного аккаунта. Дополнительный лимит Nginx ограничивает запросы страницы входа. CSRF-токен и точный `Origin` обязательны для входа и выхода. Имя хоста должно совпадать с установленным onion-адресом. WebSocket требует действующую сессию и совпадающий `Origin`.

После входа открывается меню:

- **Рабочий стол**: `/novnc/vnc.html?autoconnect=1&resize=scale&path=/ws/workstation` → `127.0.0.1:16082`.
- **Настройка Tor**: `/novnc/vnc.html?autoconnect=1&resize=scale&path=/ws/gateway` → `127.0.0.1:16081`.

Значение параметра noVNC **1.6 из Debian 13** `path=/ws/...` задаёт WebSocket `/ws/...` от корня этого же сайта. Все файлы noVNC находятся локально в `/usr/share/novnc`; сторонние шрифты, CDN и телеметрия не подключаются. Авторизацию всех ресурсов и рукопожатий WebSocket проверяет `auth_request`; недоступный backend не открывает доступ. Исключения — только форма входа, обработчик выхода с собственной проверкой и внутренний endpoint Nginx.

Штатный `vnc.html` содержит встроенный стартовый JavaScript-модуль. Установщик вычисляет SHA-256 его точного содержимого и добавляет соответствующий хеш в CSP. Произвольные встроенные скрипты не разрешены. После обновления noVNC основной `control.sh update` должен повторно вызвать hook, чтобы обновить хеш, проверить Nginx и затем перезагрузить конфигурацию.

Сессия — 256-битный случайный токен, срок максимум восемь часов. Cookie имеет `HttpOnly`, `SameSite=Strict`, `Path=/` и ограниченный `Max-Age`. Cookie **не имеет `Secure`**: стандартная модель этого атрибута рассчитана на HTTPS, а сайт доступен как `http://….onion`. Tor Browser допускает специальные исключения для onion; комплект не полагается на их поддержку другими HTTP-клиентами. Шифрование и проверку onion-сервиса обеспечивает транспорт Tor между клиентом Tor и Tor на сервере; от серверного Tor до Nginx используется loopback. Это не защищает от компрометации браузера, телефона, хоста, гипервизора или оператора физического сервера. Используйте проверенный сохранённый onion-адрес. Нельзя переносить эту конфигурацию на обычный публичный HTTP-домен. Заголовки CSP и запрет фреймов задаёт Nginx.

Для noVNC используйте актуальный Tor Browser со включённым JavaScript: он поддерживает защищённый контекст onion-сайта без HTTPS. Обычный браузер через SOCKS может ограничивать нужные noVNC API. [Tor описывает защищённые контексты onion](https://onionservices.torproject.org/apps/web/checklist/); JavaScript нужен для работы рабочего стола.

**Выход из вебсеанса не разрывает уже подключённый WebSocket.** Перед выходом заблокируйте экран в каждой открытой гостевой машине, затем закройте все окна её рабочего стола и выполните выход в меню. То же ограничение действует при истечении срока сессии и перезапуске auth-службы. Новые подключения после выхода отклоняются; уже установленный туннель может продолжать работать.

`/etc/oniondesk/credentials.json` — файл `root:root`, `0600`: `login`, `password`, `totp_secret`, `otpauth_uri`. Основной `control.sh credentials` показывает его только по явной команде владельца; установщик не выводит секреты в общий лог. Храните резерв пароля и TOTP-секрета отдельно от сервера в защищённом хранилище. Знание TOTP-секрета позволяет создавать коды. Повторная установка сохраняет все данные входа и не сбрасывает их автоматически. При несогласованных файлах установка прекращается.

`/etc/oniondesk/auth.json` — отдельный производный файл `root:root`, `0600`, без открытого пароля. Для пароля используется scrypt N=131072, r=8, p=1 с уникальной 32-байтовой солью. Runtime получает только этот файл через systemd `LoadCredential`; TOTP-секрет необходим ему для проверки кодов. Код и шаблоны в `/opt/oniondesk/frontend` принадлежат root, недоступны службе для записи. Служба `oniondesk-auth` работает без shell и привилегий, может писать только в `/var/lib/oniondesk/auth`. Сессии хранятся в памяти, состояние защиты от повтора TOTP — в приватном файле на диске.

Nginx принимает соединения только на `127.0.0.1:18080`; auth — только на `127.0.0.1:18081`. Tor направляет onion-порт 80 на первый порт. Hook проверяет `nginx -t`, затем развёрнутую конфигурацию `nginx -T` на отсутствие внешних TCP-listen. При ошибке сайт Nginx восстанавливается и auth-служба не запускается/не перезапускается. Из чужих конфигов ничего не удаляется. Штатная ссылка `sites-enabled/default` отключается только при совпадении адреса ссылки и контрольной суммы conffile пакета Debian. Изменённый default требует ручной проверки. Hook не запускает Nginx: основной установщик сначала держит его masked, затем повторно выполняет `nginx -t`, снимает mask и запускает службу.

Локальные тесты backend не заменяют развёртывание. Перед реальным использованием основной установщик обязан пройти `nginx -t` на целевом сервере, после чего владелец проверяет вход, запрет анонимного открытия файлов noVNC, оба рабочих стола и выход. Пароль, TOTP-коды и секреты не передавайте в URL или журналы.

Первичная документация: [Nginx auth_request](https://nginx.org/en/docs/http/ngx_http_auth_request_module.html), [WebSocket proxying](https://nginx.org/en/docs/http/websocket.html), [RFC 6238 TOTP](https://www.rfc-editor.org/rfc/rfc6238), [systemd credentials в Debian 13](https://manpages.debian.org/trixie/systemd/systemd.exec.5.en.html), [шифрование onion-сервисов](https://community.torproject.org/onion-services/overview/).
