# Воспроизводимые проверки Docker

Из корня комплекта:

```sh
bash tests/docker/run.sh /absolute/path/to/test-logs
```

Команда собирает Debian 13, устанавливает реальные пакеты сервера, запускает unit-тесты, ShellCheck и два браузерных прогона Chromium. Исходники монтируются только для чтения; контейнер не получает Docker socket, host `/dev`, privileged, опубликованные порты или пользовательские диски. Логи и снимки экрана сохраняются в указанной папке. Контейнер автоматически удаляется, тестовый образ `oniondesk-test:debian13` остаётся.

`smoke.py` поднимает настоящий Nginx, password/TOTP backend, websockify и два небольших RFB-сервера. Проверяет пароль, TOTP, CSRF, Origin, отказ чужому Host, реальные WebSocket upgrade, отозванный сеанс, ограничение запросов входа, loopback-only TCP, noVNC 1.6 и CSP. Chromium действительно получает и рисует заданный RFB-пиксель. Тестовый relay `127.0.0.1:80 → 127.0.0.1:18080` нужен только внутри контейнера, чтобы браузер использовал обычный onion HTTP origin; порты host не публикуются.

`app-smoke.py` запускает локальный мастер с подставными USB/remote backend. Проверяет семь экранов, шесть карточек Tails, переключатель марки компьютера, подсказки и отсутствие горизонтального переполнения на 1440×1000 и 390×844. Он ничего не скачивает, не покупает, не записывает на настоящие USB и не подключается к серверу.

`guest-inspect.sh` — отдельная ресурсоёмкая проверка официального Whonix 18.2.1.9: полные SHA-512/OpenPGP, sparse-извлечение, реальный libguestfs и XML schema. Она ожидает архив, `.asc`, `derivative.asc` в `/artifacts`, каталог журналов `/logs` и комплект в `/workspace/outputs/remote-desktop-kit`. Перед запуском требуется минимум **50 GiB физического свободного места** на смонтированной файловой системе `/artifacts`; большой виртуальный размер Docker disk этого не заменяет. Скрипт проверяет доступное место до извлечения. `guest-smoke.py` использует только disposable overlays поверх read-only bases и QEMU **TCG**, сохраняет реальные экраны через QMP. Это не проверка KVM, systemd host, production libvirt/passt или полной установки Telegram.

Фактически завершённые результаты и оставшиеся границы перечислены в `RESULT.md`. Наличие сценария проверки не означает, что его прогон завершился успешно.
